# comix.to upload API (captured 2026-10-23)

Private API, no public docs. Captured from the site's own upload page.

## Common headers
```
Accept: application/json
X-Requested-With: XMLHttpRequest
X-Rt: 0
```
Auth is the browser session cookie (HttpOnly). The `accessToken` in localStorage
does NOT authenticate on its own (tested with and without "Bearer").

## Endpoints that work without the browser token
| Call | Notes |
|---|---|
| `GET /api/v1/user` | `result` = user, or `null` when logged out. `userAbilities.createChapter` |
| `GET /api/v1/groups/{gid}/titles?page=1&limit=28` | numeric `id` + `hid` of every title the group has |
| `GET /api/v1/groups/uploadable?keyword=&limit=8` | groups you can credit |
| `GET /user/upload/{hid}` (HTML) | `<script id="initial-data">` JSON has the numeric manga id (`["manga","detail",<id>]`) |
| `GET /api/v1/user/uploads?limit=20&page=1` | your uploads: `id, mangaId, number, volume, name, status (pending/accepted/rejected), isProcessed, errors` + `counts` |
| `DELETE /api/v1/user/uploads/{id}` | `{"status":"ok","result":true}` |

## Endpoints that need the browser token
`GET /api/v1/manga?keyword=...`, `/api/v1/manga/{hid}`, `/api/v1/manga/{hid}/chapters`,
`/api/v1/groups/{gid}/chapters` all return `403 {"code":"missing_token"}` without the
`_=` query param (20 chars, generated by obfuscated `secure-*.js`).

## Upload flow (3 steps)
1. `POST /api/v1/uploads/init` (JSON)
   ```json
   {"manga_id":12345,"group_id":678,"number":1,"volume":1,"title":"...","is_official":false,"total_bytes":38000000}
   ```
   Optional: `"replace_chapter_id": <id>` to replace an existing upload's file.
   Response: `{"upload_id":"11500000","chapter_id":11500000,"chunk_size":3145728,"total_bytes":...,"chunk_url":"/upload/chunk/11500000","upload_token":"...","offset":0}`
   (`upload_token` and `offset` added by the site on 2026-10-24.)
2. `PUT {chunk_url}` once per chunk (3 MiB), raw bytes
   ```
   Upload-Token: <upload_token from init>   (required since 2026-10-24, otherwise 403 "invalid upload token")
   Content-Type: application/octet-stream
   Content-Range: bytes 0-3145727/38000000
   ```
   Response: `{"total":38000000,"received":3145728}`
3. `POST /api/v1/uploads/{upload_id}/finalize` (no body)
   Response: `{"ok":true,"upload_id":"...","chapter_id":...,"manga_id":...,"size_bytes":...,"status":"pending"}`

Archive: .zip / .cbz / .cbr / .rar / .7z, up to 1 GB, pages in reading order.

Metadata-only edit of an upload: the edit page calls an update with
`{"number","volume","title","group_id","is_official"}` (endpoint not captured yet).
